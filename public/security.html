Security Architecture & Data Governance

Data Isolation: PostgreSQL Row Level Security (RLS) • Transmission: HTTPS / TLS 1.3 • AI Governance: Server-Side API Isolation

TechPath is built on a zero-trust, defense-in-depth architecture. This page documents our technical safeguards, cryptographic standards, database security policies, rate-limiting frameworks, and responsible disclosure protocols.

1. End-to-End Cryptography & Data Protection

TechPath enforces cryptographic standards across every communication channel and data store:

  • Encryption in Transit: All HTTP network requests between your browser, reverse proxies, and microservices require HTTPS enforced via TLS 1.3 with HSTS headers.
  • Encryption at Rest: Database volumes hosted on Supabase (PostgreSQL) and object storage buckets employ AES-256 block encryption managed under certified hardware security modules.
  • Password Hashing: User credentials are protected using industry-standard bcrypt or Argon2 cryptographic salts, ensuring zero plaintext password persistence.
02

2. Supabase Row Level Security (RLS) & Tenant Isolation

In multi-tenant educational platforms, data leakage between students is a major concern. TechPath solves this at the database engine level through PostgreSQL Row Level Security (RLS):

-- Architectural Guarantee

CREATE POLICY "Users can only access their own profile" ON profiles

FOR ALL USING (auth.uid() = id);

Even if a client script attempts to craft a malicious SQL query, the database itself rejects any attempt to read or modify another user's notes, flashcards, study timer counts, or uploaded resumes.

03

3. Zero Client API Key Exposure Architecture

To prevent API key theft, quota exhaustion, and unauthorized usage:

  • Server-Side AI Proxies: All Google Gemini API keys, OpenAI tokens, and Supabase service-role credentials reside exclusively on the server runtime in environment variables (.env).
  • No Client Secrets: Frontend bundles deliver only public publishable keys scoped strictly by database RLS.
  • Session Validation: AI endpoints require verified JWT session headers before processing inference requests.
04

4. File Upload Limits & Malware Defense

Files uploaded to the PDF Analyzer, AI Notes, or Resume Builder are subject to strict ingestion constraints:

MIME Type Verification Strictly limited to application/pdf and image/jpeg,png,webp. Executables (.exe, .sh, .bat) are rejected.
Payload Size Limits Maximum file upload size is capped at 25MB to prevent memory exhaustion and zip-bomb attacks.
Sanitized OCR Memory PDF streams are parsed in isolated Web Worker sandboxes to protect the user's browser runtime.
05

5. Rate Limiting & Abuse Prevention

TechPath enforces sliding-window rate limits across authentication and AI generation endpoints:

  • Auth Throttling: Failed login attempts are throttled exponentially to mitigate brute-force and credential stuffing attacks.
  • AI Inference Spend Caps: Per-user burst and hourly token quotas prevent abuse of costly LLM infrastructure.
  • IDE Execution Isolation: User code executed in the browser IDE runs in an isolated Web Worker or sandboxed iframe with disabled network fetch capabilities.
06

6. Secure Logging & Zero PII Exposure

Our server telemetry records operational health without compromising student privacy:

  • Plaintext passwords, payment details, and full document contents are explicitly redacted before log dispatch.
  • Server error stacks are sanitized before delivery to user browsers; clients receive generic, human-readable error messages.
  • Production database backups are encrypted and stored in geo-redundant regions with limited administrator access.

Guidelines for Responsible Reporting:

  • Report details immediately to lakkimsettirahulashokh@gmail.com.
